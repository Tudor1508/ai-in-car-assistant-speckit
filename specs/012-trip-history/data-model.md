# Data Model: Trip History

## Historical Trip

An immutable saved instance of the selected route. A new row is created only by the explicit **Save trip** action. Each explicit save is a separate journey, even when its endpoints and geometry match a previous row.

| Field | Type / rule | Source and purpose |
|---|---|---|
| `id` | 32-character lowercase hexadecimal string; primary key | Generated by the backend. Stable trip identifier and deterministic page tie-break. |
| `owner_account_id` | 32-character string; required FK to `accounts.id`, `ON DELETE CASCADE` | Always derived from `require_account`; used to scope all list and summary queries. Never returned to the browser. |
| `created_at` | UTC timestamp with timezone; required | Set by the backend at explicit save time. Newest/oldest ordering and displayed planning time. |
| `origin_label`, `destination_label` | Trimmed string, 1–255 characters | Selected place labels, snapshotted so later display does not rely on provider lookup. |
| `origin_latitude`, `destination_latitude` | Decimal WGS84, -90 through 90, six fractional digits | Selected endpoint coordinates; endpoint markers and fallback viewport. |
| `origin_longitude`, `destination_longitude` | Decimal WGS84, -180 through 180, six fractional digits | Selected endpoint coordinates; endpoint markers and fallback viewport. |
| `vehicle_id` | 32-character hex string; required snapshot value, no vehicle FK | Identifies the vehicle selected at save time. Intentionally survives vehicle deletion. Backend verifies the vehicle belongs to the active account before snapshotting. |
| `vehicle_snapshot` | JSON object, strict response shape | Vehicle `id`, `name`, `model`, `type`, plus `current_level_percent`, `available_range_km`, and `maximum_range_km` used by the selected preview/map. Name/model/type are copied from the owner-scoped vehicle row; range values are recomputed from its saved range and the validated current percentage. |
| `route_preference` | Required enum: `fastest`, `shortest`, `scenic` | The selected option, not the preview request value `all`. |
| `distance_m` | Non-negative numeric scalar | Selected route's distance; canonical scalar for summaries and card display. |
| `duration_s` | Non-negative numeric scalar | Selected route's estimated driving duration; canonical scalar for summaries and card display. Does not include stop dwell time. |
| `route_snapshot` | Required JSON object validated by route snapshot schemas | Saved `LineString` geometry (`[longitude, latitude]`), feasibility status/message and unreachable-stop details, route legs, ordered stops, and optional selected scenic attractions/restaurants. Contains no duplicate distance or duration values. |

### Relationships and indexes

- Each historical trip belongs to exactly one account. Account deletion cascades to owned history, matching favorites and other account-owned data.
- Vehicle identity and presentation are values copied at save time, not a live foreign-key relationship. Later edits/deletion do not change the historical trip.
- Add `ix_trip_history_owner_created` on `(owner_account_id, created_at, id)` for owner-scoped newest/oldest page reads and deterministic ordering.
- Add checks consistent with `TripFavorite` for ID format, trimmed endpoint labels, WGS84 bounds and six-place precision, route preference, and non-negative distance/duration. Validate nested JSON data at the Pydantic boundary; SQLite checks do not attempt to parse the route snapshot.
- No uniqueness constraint is placed on endpoints or route geometry: repeated explicit saves are distinct trips.

## API read projection

The history item assembles persisted fields into the existing trip-map shape without a routing call:

- `id`, `created_at`, `origin`, `destination`, `vehicle`, `route_preference`
- `route`: saved geometry plus the canonical `distance_m` and `duration_s`
- `feasibility`, `legs`, `stops`, `attractions`, `restaurants`: read from the validated `route_snapshot`

The `vehicle` object combines the immutable vehicle display fields and saved range summary. Its required range fields match the current `TripRoutePreview.vehicle` type, allowing the current `RouteMap` to render its incomplete-range overlay without current vehicle state.

## History Summary

Read-time aggregate scoped to `owner_account_id`, not separately persisted:

| Value | Source |
|---|---|
| `total_trips` | Count of all owner rows |
| `total_distance_m` | Sum of all owner `distance_m` values |
| `total_duration_s` | Sum of all owner `duration_s` values |

An empty history returns zero for all totals and no item rows. Cost is omitted because there is no supported cost/consumption/price entity.

## Migration and lifecycle

Add Alembic revision `0006_trip_history` after `0005_admin_dashboard`. Create the new table and owner/created index without modifying existing rows. No backfill is required because the current system has no persisted planned trips. The model has no edit/delete API; the row is a point-in-time snapshot. Account deletion cascades; vehicle deletion does not.
